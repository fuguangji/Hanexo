# HANEXO

**2D 俯視即時戰略（RTS） × 工業模擬 × 軍事擴張**

HANEXO 的核心循環是取得資源、建立工業與物流體系、發展科技、部署軍事單位，最後透過軍事佔領敵方總指揮部取得勝利。

> 目前完成 M1～M3 的可操作垂直切片。私人聯機與官方公服仍未開放；建築全集與電網已可操作，M4 自動物流、戰鬥與政策尚未實作。

## M1 地圖與單位

### 地圖
- 48 × 32 格網；地形包含平地、粗糙地形及水域。
- 水域不可通行；粗糙地形會增加尋路成本。
- 相機可平移及縮放，縮放以滑鼠游標所在位置為中心。
- 世界座標、模擬狀態與 Canvas 繪圖分離。

### 尋路與單位
- 使用 A* 尋路，採四方向移動；路徑不會斜穿格角。
- 同一格不可同時容納兩支單位；移動時會檢查下一格是否被其他單位占用。
- 群體命令會為每支單位分配鄰近目的格，避免全體擠在同一格。
- 遇到動態阻擋時會嘗試重新尋路；無可用路徑則停止。
- 目前碰撞採格網占用判斷，不是連續物理碰撞引擎。

### 採集規則
1. 普通礦井直接建在空地；礦井類建築需在對應礦點 3 格內，礦點耗盡後停止並顯示原因。
2. 每座採集建築在檢視器選擇一種產出，各產出有各自速率倍率。
3. 兩種金屬礦井分別對應普通礦與稀有礦；煉礦場每產出 1 單位另消耗石頭（見檢視器顯示）。
4. 產出進入該建築自身庫存；庫存已滿、電力不足、缺少耗材時會停止並顯示原因。

### 庫存與調撥規則
1. 每座建築各自保存庫存，不存在全國共用庫存。
2. 建築成本由總部庫存支付。
3. 建築之間只能透過調撥訂單交換物資；調撥建立時先扣除來源並預留目的地容量，抵達後才入庫。
4. 目的地只接收自己用得到的資源（工廠：配方原料；發電廠：其燃料；攻擊站：其彈藥；倉庫與總部：全部）；不接收的資源不會出現在調撥表單。
5. 調撥由玩家手動建立；自動物流屬於 M4 後續工作。

### 產能與排程
- 一座工廠可同時執行多種配方，共用總產能；各工作以百分比分配，總和不可超過 100%。
- 新增工作預設 25%，每次可調整 10 個百分點；未分配的產能閒置。
- 品質乘算生產速度；目前品質固定為 1.0。
- 用電工廠在電網不足時依滿足率減速，狀態顯示「電力不足」。

### 原子化生產結算
每個批次完成時先檢查全部原料及產品、副產品容量，成立才一次扣料並產出；缺料或滿倉時停在完成點等待，不會半完成。

## M4 電網與攻擊站（部分完成）

### 電網
- 全地圖單一全域電網（尚無供電範圍、儲能或多電網）。
- 容量 = 所有「有燃料」的發電廠額定輸出；需求 = 運作中的用電建築；滿足率 = min(1, 容量 / 需求)。
- 滿足率同時縮放採集速率與生產速度。
- 發電廠只燃燒自身庫存燃料（火力：石油；核電：鈾），消耗量與負載成正比；需手動調撥燃料。
- 介面資源列有電力指示（目前輸出 / 容量）。

### 攻擊站
- 可放置，會顯示射程環與彈藥庫存；缺彈藥（或機場沒有停放飛機）時顯示未就緒原因。
- **目前不會造成任何傷害**，實際戰鬥屬於 M5。

### 升級路線（僅記錄，尚未實作）
設計表中的升級路線與政策系統尚未實作，也沒有以科技限制建造；所有 29 種建築目前一開始即可建造。

## 畫質設定

畫質設定從遊戲邏輯與介面中獨立出來（`src/settings/graphics.js`），由主選單與遊戲中頂欄的「畫質設定」開啟。

| 項目 | 說明 |
|---|---|
| 畫質等級 | 自動、低、中、高、極致。自動會依裝置性能起始（核心數、記憶體、是否為行動裝置、是否要求減少動態效果）。 |
| 渲染解析度 | 50%～100%。實際畫布像素比 = min(裝置像素比, 該等級上限) × 解析度。 |
| 幀率上限 | 30 FPS、60 FPS 或跟隨螢幕更新率。 |
| 畫面效果 | 建築陰影、地形紋理、建築與礦點細節、選取單位路徑、顯示 FPS。 |

| 等級 | 像素比上限 | 解析度 | 幀率 | 陰影 | 地形紋理 | 細節 | 路徑 |
|---|---:|---:|---:|:---:|:---:|:---:|:---:|
| 低 | 1 | 75% | 30 | 關 | 關 | 關 | 關 |
| 中 | 1.5 | 100% | 60 | 開 | 關 | 開 | 開 |
| 高 | 2 | 100% | 60 | 開 | 開 | 開 | 開 |
| 極致 | 3 | 100% | 螢幕 | 開 | 開 | 開 | 開 |

規則：
- 手動調整任一細項後，等級顯示為「自訂」。
- 自動模式下，若連續兩個取樣視窗（各約 90 個繪製幀）的平均幀時間都超過目標的 1.4 倍，會自動降一級並通知玩家；**同一次遊玩不會自動調高**，避免畫質來回跳動。
- 設定保存在瀏覽器 `localStorage`（鍵名 `hanexo.graphics.v1`）；儲存失敗（私密瀏覽、容量已滿）時仍可使用，只是不會保存。
- 沒有單位在移動時，畫面只以低頻重繪；此時 FPS 讀數顯示「待機」。

## 共用帳號整合

- 帳號中心統一使用 `https://fuguangji.github.io/game/account/`，不在 HANEXO 另建登入／註冊頁。
- 透過 `https://fuguangji.github.io/game/account/auth-bootstrap.js` 載入共用 Firebase Authentication 狀態，使用 `window.SITE_AUTH.readyPromise` 等待初始狀態，並監聽 `site:auth-state` 更新介面（實作在 `src/account/account.js`）。
- 頂欄帳號按鈕顯示登入狀態：確認中、已登入（顯示名稱）、未登入。點擊後導向共用帳號中心，並附帶目前頁面的 `returnTo`，登入後返回 HANEXO。
- 帳號中心只接受已登記路徑的 `returnTo`。HANEXO 部署在 `/Hanexo/`，已在 `fuguangji/game` 的 `account/index.html`（`RETURN_PATH_PREFIXES`）登記；若沒有這項登記，登入後會被導回 NEON-FORMULA。
- 登入狀態以網站來源為單位保存，因此**只有部署在 `https://fuguangji.github.io` 時才會共用登入**。本機開發網址（`localhost`）會顯示「登入／註冊」，點擊前往帳號中心但不帶 `returnTo`，遊戲仍以訪客身分可玩。
- 載入逾時（8 秒）或服務失敗時會停止「確認帳號中…」，改回可用狀態，不會卡住按鈕。
- 未登入仍可使用本機個人模式；不將 UID 當成授權憑證，也不把 ID Token 暴露給遊戲介面。
- **目前僅完成帳號身分連結與狀態顯示，不代表雲端存檔已完成。** 雲端存檔、版本衝突處理及跨裝置同步仍待 M7 存檔系統與專用後端介面實作。

## 面板與介面管理

### 版面
- 桌面：左側控制面板加全高地圖，整個遊戲畫面不捲動頁面。
- 平板與手機（寬度 900px 以下）：地圖佔滿畫面，控制面板成為底部抽屜；抽屜標題列會顯示目前選取的單位或建築。
- 地圖上方的資源列常駐顯示總部庫存，不必展開面板。
- 地圖右上角工具列：移動模式、放大、縮小、顯示整張地圖、回到總部。窄螢幕開局會聚焦在總部，而不是縮成看不清單位的整張地圖。
- 建造模式會在游標所在格顯示預覽：綠色可建造、紅色不可；建造失敗時會說明缺少哪些資源。

### 面板
- 所有側邊功能面板採用可展開／收合的控制面板；預設全部收合，玩家按分類標題展開。
- 面板分類：戰場概況（含任務目標）、建置管理、單位與建築資訊（含工廠生產排程）、物流與物資調撥、建築升級、科技樹、操作說明。
- 建築升級與科技樹目前僅建立獨立入口與未開放提示；升級規則、研究系統及實際操作尚未實作。
- 檢視器與調撥表單只在內容改變時才更新 DOM，並且不會在玩家操作下拉選單或輸入框時重建。

## 視覺方向

- 整體採用重型機具控制櫃風格：機油綠灰底色、鉚釘鋼板面板、凹陷式 LCD 讀數窗、LED 指示燈。
- 訊號橘為主要操作色，磷光綠表示正常與數值，警示黃只用於警示斜紋與警告。
- 標題與數值使用 Big Shoulders Display，內文使用 Noto Sans TC；字型載入失敗時退回系統字型。
- 戰術地圖採用深色工業地表；普通金屬礦以 M 標示、稀有金屬礦以 R 標示。
- 建築依功能呈現不同輪廓：總部、工廠煙囪、倉庫屋頂、礦井井架、油井抽取架、伐木場及採石設備。
- 尊重「減少動態效果」設定：自動畫質會降為低，介面轉場時間縮到最短。

## 自動建置與部署

部署由 **`fuguangji/Hanexo` 本身的 GitHub Actions** 單獨負責，不再經過個人網站儲存庫轉存建置產物。

- 推送至 `main`：執行測試、建置，成功後發布 GitHub Pages。
- Pull Request：只執行測試與建置驗證，不發布網站。
- 手動觸發：可在 Hanexo 儲存庫的 Actions 頁面執行 `Build and Deploy HANEXO`。
- Node.js 使用 24；有 `package-lock.json` 時使用 `npm ci`，否則使用 `npm install`。
- 發布來源為 Vite 的 `dist/`。
- 部署使用 GitHub Actions 的 Pages 權限與 OIDC，不需要個人 PAT。
- 個人網站 `fuguangji.github.io` 僅管理根網站，不再輪詢、建置或部署 HANEXO。

**GitHub Pages 設定要求：**請確認 Hanexo 儲存庫的 Settings → Pages → Build and deployment → Source 設為 **GitHub Actions**。若首次部署尚未啟用 Pages，先完成此設定再重新執行 workflow。

# HANEXO

**2D 俯視即時戰略（RTS） × 工業模擬 × 軍事擴張**

HANEXO 的核心循環是取得資源、建立工業與物流體系、發展科技、部署軍事單位，最後透過軍事佔領敵方總指揮部取得勝利。

> 目前完成 M1～M3 的可操作垂直切片。私人聯機與官方公服仍未開放；M4 自動物流與能源系統尚未實作。

## 操作方式

| 操作 | 功能 |
|---|---|
| 滑鼠左鍵 | 選取單位或建築 |
| 左鍵拖曳 | 框選多支單位 |
| Shift + 左鍵 | 加選／取消選取單位 |
| Ctrl+A | 選取全部我方單位 |
| 滑鼠右鍵 | 對選取單位下達群體移動命令 |
| 滑鼠中鍵拖曳 | 平移地圖相機 |
| 滑鼠滾輪 | 以游標位置為錨點縮放 |
| 空白鍵 | 暫停／繼續 |
| Esc | 取消建築放置 |

建築建造：在左側選擇建築，再點擊地圖空地。伐木場、採石場與油井可直接建在空白可通行地塊；金屬礦場必須靠近普通金屬礦或稀有金屬礦（3 格內）。

物資調撥：選取來源建築，在「手動物資調撥」選擇目的地、資源與數量，建立運輸訂單。物資離開來源庫存後會經過運輸時間，抵達才會進入目的地庫存。

## M1 地圖與單位

### 地圖
- 48 × 32 格網；地形包含平地、粗糙地形及水域。
- 水域不可通行；粗糙地形會增加尋路成本。
- 相機可平移及縮放，縮放以滑鼠游標所在位置為中心。
- 世界座標、模擬狀態與 Canvas 繪圖分離。

### 尋路與單位
- 使用 A* 尋路，採四方向移動；路徑不會斜穿格角。
- 同一格不可同時容納兩支單位；移動時會檢查下一格是否被其他單位占用。
- 群體命令會為每支單位分配鄰近目的格，避免全體擠在同一格。
- 遇到動態阻擋時會嘗試重新尋路；無可用路徑則停止。
- 目前碰撞採格網占用判斷，不是連續物理碰撞引擎。

## M2 建築與資源

### 資源分布
| 類型 | 採集資源 | 初始儲量 | 開採方式 |
|---|---|---:|---|
| 普通金屬礦 | 普通金屬 | 2,400 | 金屬礦場需在礦點 3 格內 |
| 稀有金屬礦 | 稀有金屬 | 1,200 | 金屬礦場需在礦點 3 格內 |

**資源分類原則：**地圖上只生成普通金屬礦與稀有金屬礦兩種礦點。木頭、石頭、石油不再生成獨立資源節點，對應採集建築可直接放在空白可通行地塊上持續開採。

### 建築
| 建築 | 建造成本 | 功能 |
|---|---|---|
| 總部 | 初始建築 | 起始資源、建造成本支出 |
| 伐木場 | 35 木、10 石 | 在空白地塊直接開採木頭 |
| 採石場 | 30 木、15 石 | 在空白地塊直接開採石頭 |
| 油井 | 45 木、35 石 | 在空白地塊直接開採石油 |
| 金屬礦場 | 40 木、30 石 | 開採附近普通金屬礦或稀有金屬礦 |
| 倉庫 | 65 木、55 石 | 3,000 單位獨立庫存 |
| 工廠 | 90 木、90 石 | 生產配方及副產品 |

### 庫存規則
1. 每座建築各自保存庫存，不存在可讓所有建築直接讀取的全國共用庫存。
2. 採集產出進入採集建築自身庫存。
3. 建築成本目前由總部庫存支付。
4. 建築之間只能透過調撥訂單交換物資。
5. 調撥建立時先扣除來源物資並預留目的地容量；運輸完成才入庫。
6. 本階段的調撥由玩家手動建立；自動供應與物流網路屬於 M4。

## M3 工業生產

### 目前配方
| 配方 | 原料 | 產品 | 副產品 | 基礎週期 |
|---|---|---|---|---:|
| 煉鋼 | 3 普通金屬、1 石頭 | 2 鋼 | 1 爐渣 | 5 秒 |
| 製箭 | 2 木頭、1 鋼 | 4 箭 | 0.2 金屬碎屑 | 3 秒 |
| 彈藥 | 2 普通金屬、1 鋼、1 石油 | 4 子彈 | 0.5 金屬碎屑 | 4 秒 |
| 電池 | 2 普通金屬 | 1 電池 | 0.2 化學廢料 | 4 秒 |
| 冷凍劑 | 1 石頭、1 電池 | 1 冷凍劑 | 0.25 化學廢料 | 5 秒 |

配方是資料驅動定義，後續新增工廠或配方不應要求重寫模擬核心。

### 產能與排程
- 一座工廠可同時執行多種配方。
- 所有生產工作共用工廠總產能；各工作以百分比分配，總分配不可超過 100%。
- 新增生產工作預設分配 25%，玩家可以每次調整 10 個百分點。
- 尚未分配的產能保持閒置，不自動挪用其他工作的比例。
- 工廠品質會乘算生產工作速度；目前品質初始值為 1.0，升級介面尚未實作。

### 原子化生產結算
每個生產批次完成時，系統先檢查全部原料及產品、副產品所需容量。只有條件全部成立才一次扣除原料並加入所有產出。若缺料或庫存空間不足，該批次停在完成點等待條件恢復，不會發生只扣原料、未產出產品的半完成狀態。

## 面板與介面管理

- 所有側邊功能面板採用可展開／收合的工業控制面板；預設全部收合，玩家按分類標題展開。
- 面板分類：戰場概況、建置管理、單位與建築資訊（含工廠生產排程）、物流與物資調撥、建築升級、科技樹、操作說明及任務目標。
- 建築升級與科技樹目前僅建立獨立入口與未開放提示；升級規則、研究系統及實際操作尚未實作。
- 側邊資訊僅在對應面板展開時更新，避免每個 HUD 更新週期都重建收合面板的 DOM。

## 視覺方向

- 整體採用重工業／軍工基地視覺：石墨灰鋼板、磨砂金屬、警示黃、鏽紅與分層儀表面板。
- 主選單與遊戲 HUD 使用工業面板、鉚接邊框、警示條紋及高對比資訊層級。
- 戰術地圖採用較深的工業地表色調；普通金屬礦以 M 標示、稀有金屬礦以 R 標示。
- 建築依功能呈現不同輪廓：總部、工廠煙囪、倉庫屋頂、礦井井架、油井抽取架、伐木場及採石設備。

需求：Node.js 24 或以上。

```bash
npm install
```

```bash

```

**https://fuguangji.github.io/Hanexo/**

## 自動建置與部署

部署由 **`fuguangji/Hanexo` 本身的 GitHub Actions** 單獨負責，不再經過個人網站儲存庫轉存建置產物。

- 推送至 `main`：執行測試、建置，成功後發布 GitHub Pages。
- Pull Request：只執行測試與建置驗證，不發布網站。
- 手動觸發：可在 Hanexo 儲存庫的 Actions 頁面執行 `Build and Deploy HANEXO`。
- Node.js 使用 24；有 `package-lock.json` 時使用 `npm ci`，否則使用 `npm install`。
- 發布來源為 Vite 的 `dist/`。
- 部署使用 GitHub Actions 的 Pages 權限與 OIDC，不需要個人 PAT。
- 個人網站 `fuguangji.github.io` 僅管理根網站，不再輪詢、建置或部署 HANEXO。

**GitHub Pages 設定要求：**請確認 Hanexo 儲存庫的 Settings → Pages → Build and deployment → Source 設為 **GitHub Actions**。若首次部署尚未啟用 Pages，先完成此設定再重新執行 workflow。

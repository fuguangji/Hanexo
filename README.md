# HANEXO

**2D 俯視即時戰略（RTS） × 工業模擬 × 軍事擴張**

HANEXO 的核心循環是取得資源、建立工業與物流體系、發展科技、部署軍事單位，最後透過軍事佔領敵方總指揮部取得勝利。

> 專案狀態：核心玩法原型開發中。本文明確區分已實作功能、已確立設計與尚未完成項目。

## 遊戲設計概要

### 核心定位
- 類型：即時戰略（RTS）。
- 視角：2D 俯視。
- 地圖：正方形網格。
- 領土：透過軍事單位佔領。
- 時間：即時推進，可調速及暫停。
- 勝利條件：佔領敵方總指揮部。

### 三種模式
| 模式 | 建築複雜度 | 科技樹 | 模擬方式 |
|---|---|---|---|
| 個人模式 | 較高 | 深且廣 | 本機模擬 |
| 私人聯機 | 較低 | 短且簡易 | 房主權威（Host-authoritative） |
| 官方公服 | 較低 | 短且簡易 | 官方伺服器 |

三種模式應共用遊戲核心，透過模式設定及資料配置調整建築、配方、科技與規則，不維護三套互不相容的遊戲程式。

## 核心系統規劃

### 1. 世界與地圖
- 以格網座標管理地形、建築、單位及領土。
- 世界資料與 Canvas 繪圖分離。
- 地圖大小、生成方式、視野遮蔽及地圖邊界仍待決定。
- 後續加入相機移動、縮放、選取框及多單位操作。

### 2. 時間與模擬
- 模擬採固定步長更新（Fixed Timestep）。
- 畫面更新使用 requestAnimationFrame。
- 遊戲速度透過時間倍率（Time Scale）調整，不直接任意改變核心模擬頻率。
- 暫停時停止推進模擬時間，但畫面仍可繪製。
- 模擬、渲染、輸入及 UI 分離。

### 3. 資源、工廠與生產

已確立的生產規則：
1. 每座工廠有自己的獨立庫存。
2. 工廠可以自由切換生產配方。
3. 同一工廠可以同時生產多種產品，並共享總產能。
4. 生產活動全面考慮副產品。
5. 工廠只能使用自身庫存中的原料，工廠之間必須透過物流交換物資。

建議以資料驅動方式定義資源、建築、配方及升級。配方資料至少描述原料、產出、副產品、所需時間、能源需求及產能占用。

生產結算應保持原子性：單次生產批次在原料與必要產出空間均可用時才完成扣料及入庫，避免物資狀態不一致。

### 4. 物流
- 玩家指定供應來源與接收對象。
- 系統自動安排物資運輸。
- 每筆運輸應記錄來源、目的地、資源種類、數量、運輸進度及狀態。
- 物流速度、容量、距離成本、路徑及中斷規則尚待設計。
- 電力是否使用獨立電網，不與一般物資共用物流，仍待決策。

### 5. 建築與升級
- 建築可以升級產能。
- 建築可以升級品質或專屬功能屬性。
- 不同建築可以有不同升級屬性，例如雷達視野加成。
- 升級效果應由資料定義，不把每一種建築的規則寫死在 UI 中。

### 6. 軍事與領土
- 規劃完整軍種、軍事設施、單位部署及戰場資訊系統。
- 單位移動、戰鬥、視野及佔領規則由模擬核心統一管理。
- 佔領敵方總指揮部為主要勝利條件。
- 目前原型只包含簡化移動及總部佔領判定，並不代表正式戰鬥系統已完成。

### 7. 科技與政策
- 科技樹負責解鎖建築、資源、配方、單位及功能。
- 政策的每秒產能由政策品質決定。
- 部分建築可以提升政策產能。
- 科技樹依模式配置：個人模式較深廣，私人聯機與官方公服較短且簡易。

## 技術架構

### 技術選擇
| 項目 | 選擇 |
|---|---|
| 語言 | JavaScript ES Modules |
| 執行環境 | 現代瀏覽器 |
| 前端建置 | Vite |
| 畫面 | HTML Canvas 2D |
| Node.js | 24 以上 |
| 單機模擬 | 本機執行 |
| 部署 | 現有 GitHub Actions 工作流程 |

### 架構原則
- **Simulation Core**：唯一負責改變遊戲世界狀態。
- **Renderer**：讀取世界狀態並繪製，不直接修改模擬資料。
- **Input Layer**：將滑鼠與鍵盤操作轉換成遊戲命令。
- **UI Layer**：顯示狀態及提供控制。
- **Data Definitions**：以資料描述資源、建築、配方、科技、單位與模式設定。
- **Networking Layer**：未來負責命令傳輸、同步及房主權威驗證。

多人模式應以命令為同步單位，並由權威模擬端驗證命令；不要讓客戶端直接提交任意世界狀態。

### 重要資料模型（規劃）
- World：地圖、時間、玩家、實體及全域狀態。
- Entity：單位、建築、資源節點等世界實體。
- Inventory：個別工廠、倉庫及單位的庫存。
- Recipe：輸入、產出、副產品、時間及能源需求。
- ProductionJob：生產配方、產能分配與進度。
- LogisticsOrder：供應來源、接收對象及運輸狀態。
- Technology：解鎖條件與效果。
- Upgrade：建築等級與屬性變化。
- GameModeConfig：各模式可用內容與規則。
- Command：玩家提出、由模擬端驗證的操作。

## 開發流程與里程碑

採用「先完成可測試的垂直切片，再擴充完整系統」的方式。每個里程碑都要有可驗證的完成條件。

| 階段 | 工作內容 | 完成標準 |
|---|---|---|
| M0 專案底座 | 模組化、固定步長、輸入與渲染分離 | 可啟動、暫停、調速，模擬與繪圖互不耦合 |
| M1 地圖與單位 | 地圖、相機、選取、尋路、單位命令 | 多單位可穩定移動及接受命令 |
| M2 建築與資源 | 建造、資源節點、庫存、採集 | 可建立建築並管理獨立庫存 |
| M3 工業生產 | 配方、多產品排程、共享產能、副產品 | 生產結算正確，缺料及滿倉狀態可處理 |
| M4 物流與能源 | 供應設定、自動運輸、電力系統 | 工廠只能透過物流取得外部物資 |
| M5 軍事系統 | 單位類型、戰鬥、視野、佔領 | 可完成一場有攻防流程的 RTS 對局 |
| M6 科技與升級 | 科技樹、政策、品質與建築升級 | 解鎖及屬性效果可由資料配置 |
| M7 AI 與單人完整模式 | AI 決策、存檔、讀檔、平衡 | 可完成完整單人對局 |
| M8 私人聯機 | 房主權威、房間、命令同步 | 多名玩家可完成同步對局 |
| M9 官方公服 | 持續世界、伺服器管理、反作弊 | 公服可部署、監控及維護 |
| M10 發布 | 效能、相容性、操作體驗及文件 | 達成正式發布品質 |

### 每個階段的工作循環
1. 確認該階段的規格與完成條件。
2. 建立或修改模組。
3. 執行建置與測試。
4. 修正錯誤及檢查既有功能。
5. 更新 README 的完成狀態。
6. 提交 Git commit，保留可回溯版本。
7. 再進入下一階段。

## 本機開發

需求：Node.js 24 或以上。

~~~bash
npm install
npm run dev
~~~

開啟 Vite 顯示的本機網址即可。

正式建置：

~~~bash
npm run build
npm run preview
~~~

目前 package.json 的建置 base 為 /game/Hanexo/，與既有網站部署路徑一致。
